+# Astro + Feature-Sliced Design (FSD) Rules
+
+To prevent sloppiness, these strict deterministic rules apply whenever you work with Astro components, Vitest testing, or Astro content collections:
+
+1. **Strict FSD Public APIs:** 
+   - Never import internal files directly from deep entity or widget structures.
+   - 🔴 **BAD:** `import Component from '@/entities/blog-post/ui/Component.astro'`
+   - ✅ **GOOD:** `import { Component } from '@/entities/blog-post'`
+   - You MUST create an `index.ts` file in the FSD slice to export Astro components cleanly.
+
+2. **Astro 7 Content Loaders:**
+   - Legacy `src/content/config.ts` is banned. Use `src/content.config.ts`.
+   - Collections must use the `glob()` loader (e.g., `loader: glob({ pattern: "**/*.md", base: "./src/content/blog" })`).
+   - `CollectionEntry<T>` no longer has a `slug` or `render` property. Use `id` and `rendered`.
+   - Always run `pnpm astro sync` after editing schemas to update the `.astro` typings.
+
+3. **Vitest Mocking (Zero Casts):**
+   - Banned: `as any`, `as unknown as Type`.
+   - Mock properties natively. If the framework forces impossible-to-mock internal properties, explicitly use `// @ts-expect-error` inline rather than casting the object.

+import { glob } from 'astro/loaders';
+import { z, defineCollection } from 'astro:content';
+
+/**
+ * Permalink slug contract: lowercase ASCII words joined by single hyphens.
+ * The native glob() loader uses frontmatter `slug` as the entry `id`,
+ * so the URL is decoupled from the filename and never derived implicitly.
+ */
+export const SLUG_PATTERN = /^[a-z0-9]+(?:-[a-z0-9]+)*$/;
+
+const blogCollection = defineCollection({
+	loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
+	schema: z.object({
+		slug: z.string().regex(SLUG_PATTERN, 'slug must be lowercase kebab-case (e.g. "web-components-overview")'),
+		title: z.string(),
+		subtitle: z.string(),
+		description: z.string(),
+		publishDate: z.coerce.date(),
+		tags: z.array(z.string()).default([]),
+		isFeatured: z.boolean().default(false),
+	}),
+});
+
+export const collections = {
+	blog: blogCollection,

+subtitle: "Deterministic gates around non-deterministic models"
+description: "An LLM agent is only as reliable as the system around it. This post breaks down the parts of a harness: context, tools, gates, and handover."
+publishDate: 2026-10-08
+tags: ["AI", "LLM", "Agents", "Architecture"]
+isFeatured: true
+---
+
+A language model writes plausible code. Plausible is not correct. The harness is the part of the system that closes that gap.
+
+## What a harness is
+
+A harness is everything around the model that you control:
+
+- **Context:** the rules, manifestos, and file excerpts the agent sees before it acts.
+- **Tools:** the commands it can run, and the ones it cannot.
+- **Gates:** linters, type checks, and tests that fail the build when the agent is wrong.
+- **Handover:** a structured summary that lets the next session continue without guessing.
+
+## Gates beat instructions
+
+Telling an agent "never use `any`" works most of the time. A lint rule that fails CI works every time. If a rule matters, encode it as a check. Prose in a markdown file is a hint, not a guarantee.
+
+## Live verification
+
+An agent should never report a task as done based on what it wrote. It should report what it ran: the lint output, the test summary, the build result. Claims without command output are not evidence.
+
+## Scope control
+
+Agents degrade as scope grows. Small branches, one concern per pull request, and a hard checkpoint between phases keep quality stable.

+

+import type { BlogPost } from './types';
+
+const byNewest = (a: BlogPost, b: BlogPost): number =>
+  b.data.publishDate.getTime() - a.data.publishDate.getTime();
+
+export const sortByNewest = (posts: readonly BlogPost[]): BlogPost[] => [...posts].sort(byNewest);
+
+/** Explicitly featured post, otherwise the newest post. */
+export const selectFeaturedPost = (posts: readonly BlogPost[]): BlogPost | undefined =>
+  posts.find((post) => post.data.isFeatured) ?? sortByNewest(posts)[0];
+
+interface RecommendedOptions {
+  limit?: number;
+  excludeId?: string;
+}
+
+/**
+ * Legacy behavior: "recommended" = every post except the featured one.
+ * Legacy shuffled randomly; we sort by date instead so static builds are reproducible.
+ */
+export const selectRecommendedPosts = (
+  posts: readonly BlogPost[],
+  { limit = 3, excludeId }: RecommendedOptions = {},
+): BlogPost[] => {
+  const featuredId = selectFeaturedPost(posts)?.id;
+  return sortByNewest(posts)
+    .filter((post) => post.id !== featuredId && post.id !== excludeId)
+    .slice(0, limit);
+};

+export type JsonLdValue = string | number | boolean | null | JsonLdValue[] | JsonLdObject;
+export interface JsonLdObject {
+  [key: string]: JsonLdValue;
+}
+
+/**
+ * Serializes structured data for a `<script type="application/ld+json">` block.
+ * JSON.stringify does not escape "<", so a value containing "</script>" would break out
+ * of the script element (OWASP XSS). Escaping "<" as \u003c keeps the JSON valid and inert.
+ */
+export const serializeJsonLd = (data: JsonLdObject): string =>
+  JSON.stringify(data).replace(/</g, '\\u003c');
