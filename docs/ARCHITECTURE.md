# Architecture

Structure: Astro's conventions (ADR 002). This file records runtime behavior the code alone doesn't make obvious.

## State
- Theme: `astro.config.mjs` injects `src/lib/theme.js` as a hashed inline `<head>` script on every page, so it costs no request (#86). A native store over localStorage key `theme` in `src/lib/theme-store.ts`, without a state library; it re-renders on the `storage` event from other tabs and on a bfcache `pageshow`. Only the `Header` client script reads and writes it. `src/lib/theme.js` applies a stored `light` or `dark` before first paint. Without one, nothing sets `data-theme` and `prefers-color-scheme` decides; the toggle's `aria-pressed` then follows the OS theme.
- Card-to-post morph: `astro.config.mjs` also injects `src/lib/post-morph.js` as a hashed inline `<head>` script, because its `pagereveal` listener must run before the first render. On `pageswap` and `pagereveal` it names the title of the clicked card (`[data-post-card]`: the blog cards and the home writing rows, #219) and of the post header (`#post-hero`, render-blocked with `<link rel="expect">` in `BlogPostLayout`) as `post-title`, then removes the name. Cross-document view transitions only; other engines navigate normally (#210).
- Menu: no JS store. State lives in the DOM: invoker commands (`commandfor`/`command`) open and close the modal `dialog#site-menu`. Its component script has two jobs: it holds the close command and Esc's `cancel` while `data-closing` plays the closing transitions, then calls `close()` (#206); and it closes the dialog on `pagehide` so Back restores it closed. Blog categories: no client state; each category is a static page built by `getStaticPaths`, linked from `nav[aria-label="Blog categories"]` with `aria-current="page"` on the current link. `/blog/` and each category page are split at 10 posts by `paginate()`: page 1 at the base URL, then `2/`, linked from `nav[aria-label="Pagination"]` (#160).
